# DC-SDPNet

DC-SDPNet supports photovoltaic power forecasting with a dynamic number and composition of available stations.

## Environment

Install the dependencies with:

```bash
pip install -r requirements.txt
```

## Data

The preprocessed dataset used in this project is provided as a GitHub Release asset.

Release:

[`DC-SDPNet v1.0.0`](https://github.com/S-M-F-X/DC-SDPNet/releases/tag/v1.0.0)

Dataset file:

```text
pv_power_1,7_3d.npy
```

After downloading the file, place it at:

```text
dataset/pv_power_1,7_3d.npy
```

The expected dataset shape is:

```text
[time, feature, station]
```

with 227 stations and 8 features.

The dataset is distributed through GitHub Releases rather than stored directly in the Git repository because its file size exceeds the GitHub web-upload limit.

All default project paths are resolved relative to `main.py`, not to the terminal or IDE working directory. Therefore the dataset, output folders, checkpoints, and logs are found consistently when the program is started from PyCharm, a terminal, or another working directory.

## Forecast horizons

The released configurations support:

```text
q = 4, 8, 16
```

corresponding to 1 h, 2 h, and 4 h forecasting horizons.

## Unified training and checkpoint paths

The pretrained checkpoints are stored in the exact same paths used by training:

```text
output/
├─ DC_SDPNet_q4/
│  ├─ data.txt
│  └─ model/
│     └─ checkpoint.pth
├─ DC_SDPNet_q8/
│  ├─ data.txt
│  └─ model/
│     └─ checkpoint.pth
└─ DC_SDPNet_q16/
   ├─ data.txt
   └─ model/
      └─ checkpoint.pth
```

For example, running training from scratch with:

```bash
python main.py --train --pred_len 8
```

saves the best validation checkpoint to:

```text
output/DC_SDPNet_q8/model/checkpoint.pth
```

Running evaluation with:

```bash
python main.py --pred_len 8
```

loads that same file. The same rule applies to q=4 and q=16. Thus the released pretrained checkpoints and checkpoints generated by the released training pipeline share one canonical path convention.

`--train` intentionally writes to the canonical checkpoint path for the selected horizon. Back up the released pretrained checkpoint before retraining if it should be preserved.

## Training strategy

DC-SDPNet uses mixed dynamic station training. Each training batch is constructed using one of the collaboration scales:

```text
K ∈ {1, 8, 16, 32, 64, 227}
```

Station subsets are dynamically sampled during training. Validation uses the fixed Full regime with all 227 stations, and the checkpoint is updated only when the validation objective improves.

## Evaluation regimes

The released evaluation pipeline reports the four regimes used in the paper:

```text
Full       K = 227
Subset16   K = 16
Subset32   K = 32
Single227  K = 1, evaluated independently for all 227 stations
```

Subset16 and Subset32 use the fixed station sets defined in `util/config.py`. Single227 computes metrics separately for each station and then averages the 227 station-level metrics.

By default all four regimes are evaluated:

```bash
python main.py --pred_len 4
python main.py --pred_len 8
python main.py --pred_len 16
```

A single regime can also be selected, for example:

```bash
python main.py --pred_len 8 --eval_regime subset16
```

## Run log

Every run creates or appends to:

```text
output/DC_SDPNet_q{q}/data.txt
```

The file is created at program startup, before model initialization or evaluation. It records the release version, project and dataset paths, checkpoint path, horizon configuration, dynamic training station scales, fixed evaluation station IDs, device and dataset shapes, training/validation progress, checkpoint updates, and evaluation results.

During evaluation, each regime is written to `data.txt` immediately after that regime finishes. Therefore completed Full, Subset16, and Subset32 results remain available even if a later Single227 evaluation is interrupted. Avg4 and total evaluation time are written after all four regimes finish.
